# Discard raw bank text, keep cleaned fields and a fingerprint

Decided: 2026-10-31

Bank text can hold account and card numbers, and the database should keep as little of that as possible. So statements stay in memory during import and aren't kept, and raw bank text is discarded after parsing. Before anything is stored or hashed, full IBANs and card numbers are removed from every text field the row keeps, leaving a `[REDACTED]` placeholder. Only cleaned fields are kept: the posted and purchase dates, amount, merchant or recipient, payment purpose, the original amount and rate, the bank's type and category, the reference IDs (PPD ID, Ordering Party ID and transfer number), and the balance. Each row also gets a one-way fingerprint, built from its account, posted date, amount, cleaned text and its repeat count among identical rows in the statement, so an overlapping statement's rows are skipped. Once rows are stored, the text cleaning and the fingerprint format are frozen. A stored row can't be cleaned again, because its raw text is gone, and a new cleaning would give the same bank row a new fingerprint, so importing it again would store it twice. A new fingerprint format needs a new prefix and a migration that recomputes old rows from their stored fields.
